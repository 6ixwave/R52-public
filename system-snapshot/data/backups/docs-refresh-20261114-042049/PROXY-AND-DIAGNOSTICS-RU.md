## Дополнительные воспроизведённые дефекты

1. В collect_links подан результат вида `{'type':'playwright','status':200,'dom':{},'rendered':'<html></html>'}`. Получен тот же AttributeError. Нужен полноценный контракт HTML/final_url/status, а не простая замена имени поля.
2. В Ozon/Avito/Farpost вызваны поиски с page=1 и page=2 при подменённом HTTP-клиенте. URL полностью одинаковы. Счётчик в ядре растёт, а сборщик снова запрашивает первую страницу.
3. WB: синтетический вход data.products[0].sizes[0].price.product=1234500. Результат price_candidates=[]. Это доказательство неподдержанного формата, не утверждение о сегодняшнем live API WB.
4. ProxyPool с двумя тестовыми серверами выбрал индекс 0, но mark_failure увеличил счётчик индекса 1. mark_success также работает с последним alive, а не с выбранным сервером. Файл не изменён в этом этапе.
5. В журналах Avito/Farpost 404 и Ozon 403 не увеличивают failed/blocked, worker завершает поиск нулём результатов. Ядро сообщает общее EMPTY_OR_UNAVAILABLE. Подробная причина остаётся только в worker.log.

## Риски, найденные чтением кода

- В Ozon есть verify=False, в браузере AliExpress ignore_https_errors=True. Перед подключением внешних прокси требуется отдельно восстановить/проверить TLS, а не считать трафик защищённым автоматически.
- ProxyPool.mark_failure пишет полный URL прокси в журнал: при наличии user/password возможна утечка реквизитов. Секретов в ходе этой проверки не читали и не выводили.
- get_proxy не обеспечивает заявленную в комментарии паузу PROXY_COOLDOWN; выбор и результат не привязаны к одному запросу.
- requests HTTPAdapter и BaseCollector имеют вложенные повторы, возможны значительные задержки. Не проводился длительный нагрузочный тест.
- READY в sources.py означает наличие класса в реестре, а не проверенный доступ к площадке.
- AliExpress RU обновляет карточку через www.aliexpress.com, что может объяснять другую локаль. Причина отсутствия цен ещё не установлена.
- В исходниках используются отдельные профили AliExpress и новый контекст Ozon. Полная проверка отсутствия личных сессий в существующих профилях не проводилась; гарантировать безопасность аккаунтов нельзя.
