# Автосбор R-52 2.12

Запустите R52.cmd, откройте «Автосбор», выберите источник и раскройте «Новая цель». Введите поисковую фразу и нажмите «Добавить цель». Текстовая категория передаётся как поисковая фраза. Для публичной страницы раздела выберите «URL категории». При первом запуске источники и автосбор включены. Список запросов изначально пуст. Принятые товары включённых источников обновляются и без поисковых целей.

Планировщик впервые ставит задачу примерно через 15 секунд, затем раз в минуту проверяет сроки. По умолчанию поиск выполняется раз в час, обновление карточки раз в 6 часов, максимум 20 новых предложений за цикл. Для каждой цели задаётся собственный интервал или используется общий. За проход обновляются до пяти ранее принятых товаров на источник, первыми идут те, которые дольше ждали. Реальное время зависит от очереди и ответа площадки. Отдельно запущенное фоновое ядро считается работающей системой. «Запустить сейчас» ускоряет поиск, сохраняя паузу источника после ошибки.

| Блок | Изменения | Как проверить |
|---|---|---|
| А | A-storage.patch, схема v9 и настройки. Хранятся цели, интервалы, состояние источников и файлы для подтверждения импорта. | Сохранить цель, перезапустить ядро, проверить её параметры. |
| Б | B-search.patch, subprocess runner, работа с URL категории и новый метод поиска AliExpress.com. Повторно использованы пять имеющихся поисковых методов. | Добавить запрос или URL своего источника, проверить результат. Страница категории должна содержать доступные ссылки на карточки. |
| В | C-jobs.patch, обработчик поиска и обновления, защита очереди от двух параллельных проходов. Принятие только собственных результатов по пути и SHA-256 через штатный Inbox.accept. | Проверить «Входящие» с фильтром принятых, «Товары» и историю. |
| Г | D-lifecycle.patch, расписание, каталог приёма автоэкспортов, остановка с ядром. | Проверить в «Задачах» первый запуск и следующий срок. Выключить автосбор, затем остановить ядро. |
| Д | E-interface.patch, отдельный экран и локальные API. | Добавить, изменить и удалить цель, переключить источник, сохранить интервалы, запустить задачу. |
| Е | F-tests.patch, тесты интеграции, валидации, лимита, отказа одного источника и перечня экранов. | В корне проекта выполнить python -m unittest discover -s tests -v. |

## Чек-лист приёмки

- [x] Полная предварительная копия указанной папки, 13 563 файла, сравнение SHA-256.
- [x] Первый автоматический проход поставлен через 15 секунд. Все испытания использовали отдельные временные каталоги и базы.
- [x] Реальный поиск AliExpress RU по фразе RTX 5060 принёс ID 1005012437519639. В одном испытании на 36-й секунде товар был в БД. Следующий цикл начался на 75-й секунде, второе наблюдение появилось на 95-й. Цена во втором наблюдении отсутствовала, статус наличия изменился. Корректность значений на витрине отдельно не подтверждалась.
- [x] На итоговом пути через runner проверено обновление карточки, первоначально импортированной из исторического экспорта AliExpress RU. За 25 секунд получено второе наблюдение. На контролируемом экспорте отдельный тест проверяет запись двух наблюдений одной карточки с разными ценами.
- [x] Через штатный вход в локальном Chromium проверены экран, шесть источников, добавление и удаление цели, общий выключатель и ручной запуск. Обновление цели и переключение отдельного источника также проверены через API.
- [x] Отключение исключает новый запуск. На контрольном длительном процессе проверено завершение при отключении и при остановке ядра. На Windows проверен выход дочернего процесса после принудительного завершения родителя.
- [ ] Live-поиск на всех шести площадках. В испытании Avito, Ozon, WB и FarPost вернули пустой результат. Международный AliExpress завершился ошибкой процесса. Точная причина отказа на площадках не установлена. Повторный поиск AliExpress RU также один раз вернул пустую выдачу.
- [ ] Реальная категория и URL категории на каждой площадке. Для ссылок проверен локальный пример с исключением чужого домена и дубликатов.

Поле «Найдено» считает новые карточки, переданные на приём. Результаты окончательного сохранения видны в «Товарах» после прохода наблюдателя и принятия. Рабочая версия сохраняет прежние правила приёма ручных экспортов. Для запуска на рабочем профиле закройте ранее запущенное ядро и откройте R52.cmd из этой папки.
