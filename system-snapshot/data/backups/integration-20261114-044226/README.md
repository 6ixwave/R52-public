# R52 2.12

Текущий выпуск: 2.12.0. Карточки товаров в микрорайоне выстроены ровными колонками по краям экрана с линиями к своим зданиям, на «Обзоре» — топография React Bits с пресетом Sonar — UPDATE-2.12-RU.md. Результаты проверок — VERIFICATION-2.12-RU.md.

## Возможности ядра


R-52: локальный помощник для Windows. Собирает товары в одном месте, хранит историю цен, следит за целевой ценой и наличием, присылает уведомления и сводку, делает резервные копии и отвечает на вопросы о ваших товарах. Всё работает на этом компьютере, ядро не выходит во внешнюю сеть.

**Сбор данных с маркетплейсов в этой версии пока не реализован.** Товары и цены попадают в R-52 из выгрузок R-52 Eye, из прежней версии (базы D0 и data-01) и вручную. Место для будущих сборщиков подготовлено, см. раздел «Сбор с маркетплейсов».

## Что нужно

- Windows 10 или 11. Ядро и тесты работают и на Linux или macOS.
- Python 3.11 или новее с python.org.
- Microsoft Edge (он есть в Windows 10 и 11) или Google Chrome: в нём открывается окно R-52.
- Сторонние пакеты не нужны, только стандартная библиотека Python.

## Запуск

Распакуйте архив в любую папку, например `C:\R52`, и запускайте файлы из неё.

| Файл | Что делает |
|---|---|
| `R52.cmd` | открывает окно R-52, ядро запускается само |
| `R52-core.cmd` | запускает ядро с автоматическим перезапуском при сбоях, без окна |
| `R52-doctor.cmd` | проверяет Python, SQLite, папку данных и целостность базы |
| `run-tests.cmd` | запускает все тесты |

То же из командной строки в папке проекта (на Linux и macOS вместо `py -3` пишите `python3`):

```
py -3 -m r52.desktop                      окно
py -3 -m r52.desktop --print-url          ссылка входа вместо окна
py -3 -m r52 serve --console              ядро с журналом в консоли
py -3 -m r52 supervise                    ядро с автоматическим перезапуском
py -3 -m r52 doctor                       проверка окружения
py -3 -m unittest discover -s tests -v    тесты
```

### Окно и ядро

- Окно R-52 открывается в Edge или Chrome в режиме приложения: отдельное окно без адресной строки и вкладок, со своим профилем браузера в папке данных. Браузер находится сам, другой можно указать в переменной `R52_BROWSER` или параметром `--browser`. Если подходящего браузера нет, интерфейс откроется в браузере по умолчанию.
- Окно подключается к уже работающему ядру, а если ядра нет, запускает своё. Вход выполняется по одноразовой ссылке, ключ ядра в браузер не попадает.
- Своё ядро окно останавливает примерно через 12 секунд после закрытия последнего окна R-52. Если в этот момент идут задачи, ядро ждёт их завершения, но не дольше часа. Если окно так и не открылось, ядро останавливается через 2 минуты. После сбоя ядро запускается снова, до трёх раз подряд.
- Ядро, запущенное отдельно (`serve` или `supervise`), продолжает работать и после закрытия окна.
- Расписание, слежение и приём выгрузок Eye работают, пока работает ядро. Чтобы они работали и без окна, держите запущенным `R52-core.cmd` (окно консоли можно свернуть). Для автозапуска положите ярлык `R52-core.cmd` в папку автозагрузки: Win+R, `shell:startup`.
- Кнопка «Завершить работу ядра» на экране «Сервис» останавливает ядро. Чтобы продолжить, запустите `R52.cmd` снова.

## Экраны окна

- **Обзор**: сводка по товарам и целям, последние события, состояние ядра и резервных копий.
- **Товары**: поиск, фильтр по источнику, избранное и слежение, сортировка, вид сеткой или списком, добавление вручную. Карточка товара: цена и статистика, история цен с графиком, сведения со страницы товара, слежение, сравнение, добавление цены вручную.
- **Входящие**: выгрузки Eye, которые ждут решения («Принять» или «Отклонить»), а также принятые, отклонённые и файлы с ошибками.
- **Слежение**: целевая цена, снижение на заданный процент, появление в наличии; избранное с заметками; сравнения товаров.
- **Помощник**: вопросы обычным текстом, см. ниже.
- **Задачи**: быстрый запуск резервной копии, обслуживания базы, сводки и импорта, журнал задач (отменить, повторить), расписание.
- **Настройки**: уведомления, тихие часы и звук, сводка, приём файлов, помощник, резервные копии, срок хранения служебных записей, анимации. Изменения сохраняются сразу.
- **Сервис**: ядро, база данных, резервные копии, источники, выгрузка и импорт данных, журнал, завершение работы ядра.

Поиск и команды: Ctrl+K или `/`. Переход между экранами: Alt+1…Alt+8.

## Как товары попадают в R-52

1. **R-52 Eye.** Ядро следит за папками из `config.toml` (по умолчанию «Загрузки») и забирает файлы `jarvis-eye*.json` во «Входящие». Сами файлы не удаляются. Добавить файлы вручную: перетащите их на поле вверху экрана «Входящие» (или нажмите на него и выберите файлы) либо выполните `py -3 -m r52 import-eye файл.json`. Автоматическое принятие включается в настройках.
2. **Прежняя версия.** «Сервис» → «Импорт из старых версий» → «Импортировать» или `py -3 -m r52 import-legacy --d0 путь\к\D0.sqlite --data01 путь\к\data-01.sqlite`. С флагом `--dry-run` записи только подсчитываются. Базы прежней версии открываются только для чтения и не изменяются.
3. **Вручную.** «Товары» → «Добавить», в карточке товара «Добавить цену».

## Помощник

Понимает простые фразы, например:

- «найди rtx 4060», «сколько стоит rx 7600»
- «история цен rtx 4060»
- «сравни rtx 4060 и rx 7600», «сравни избранное»
- «следи за rtx 4060 до 29000», «следи за rx 7600 на 10%»
- «добавь rtx 4060 в избранное»
- «что нового», «входящие», «избранное», «слежение», «статус», «помощь»

Действия, которые меняют данные (слежение, избранное), выполняются только после подтверждения.

По умолчанию помощник отвечает по правилам. В настройках можно включить локальную модель через Ollama (модель по умолчанию `qwen2.5:7b-instruct`, порт 11434). Ответ модели принимается, только если каждое число в нём есть в фактах или в вопросе, иначе используется ответ по правилам. Так модель не может придумать цену.

## Командная строка

`py -3 -m r52 <команда>`. У всех команд есть параметр `--home ПАПКА`.

| Команда | Что делает |
|---|---|
| `serve [--port N] [--console]` | запустить ядро |
| `supervise [--console]` | запустить ядро с перезапуском при сбоях |
| `doctor` | проверить окружение и данные |
| `status [--json]` | состояние работающего ядра |
| `backup` | создать резервную копию базы |
| `backups` | показать резервные копии |
| `restore ИМЯ --yes` | восстановить базу из копии, ядро должно быть остановлено |
| `import-legacy [--d0 ПУТЬ] [--data01 ПУТЬ] [--dry-run]` | импортировать данные прежней версии |
| `import-eye ФАЙЛ...` | положить выгрузки Eye во входящие |
| `export` | выгрузить данные в ZIP (CSV и JSON) |
| `migrate` | применить миграции базы, ядро должно быть остановлено |
| `version` | показать версию |

Коды выхода: 0 успех, 1 ошибка, 2 неверные аргументы, 3 ядро уже запущено, 4 ошибка в `config.toml`, 130 прервано.

## Где хранятся данные

Папка данных берётся из переменной `R52_HOME`, иначе это `%LOCALAPPDATA%\R52` на Windows и `~/.local/share/r52` на Linux и macOS.

```
config.toml        настройки, нужные до открытия базы
data/r52.sqlite3   база
backups/           резервные копии
exports/           выгрузки ZIP
logs/              журналы ядра и окна
run/               адрес и ключ работающего ядра, сессии окна, блокировка
ui/                профиль браузера для окна R-52
```

Если `config.toml` нет, он создаётся при запуске:

```toml
[api]
port = 0                       # 0 = свободный порт, адрес всегда 127.0.0.1

[logging]
level = "INFO"                 # DEBUG, INFO, WARNING или ERROR

[display]
timezone = "Asia/Vladivostok"

[intake]
folders = ["~/Downloads"]      # где искать выгрузки Eye
```

Остальное меняется в окне на экране «Настройки» и хранится в базе. По умолчанию:

- резервная копия каждый день в 04:00, хранятся 7 ежедневных и 4 еженедельных копии;
- обслуживание базы в 05:00: удаляет завершённые задачи, прочитанные уведомления, события и отметки о файлах Eye старше 180 дней;
- сводка в 09:00;
- тихие часы с 23:00 до 08:00.

## Сбор с маркетплейсов

Не реализован. Задача сбора `collect` честно завершается со статусом BLOCKED и кодом SOURCE_NOT_IMPLEMENTED.

Точка подключения: `r52/sources.py` (реестр `REGISTRY` и протокол `Collector`) и задача `collect` в `r52/core/handlers.py`. Правила для будущих сборщиков:

- только разрешённые каналы: официальные или партнёрские API, фиды, выгрузки Eye;
- без маскировки автоматизации, подмены отпечатка браузера и обхода защиты;
- остановка при CAPTCHA, HTTP 403 или 429 без повторов в обход;
- сеть только в отдельном процессе сборщика, процесс ядра остаётся без внешней сети;
- результат проходит ту же нормализацию и проверки, что и выгрузка Eye.

## Безопасность

- API ядра слушает только 127.0.0.1. Программы обращаются к нему с ключом из `run/runtime.json`. Окно R-52 входит по одноразовой ссылке и получает свою сессию (cookie HttpOnly, SameSite=Strict). Запросы с чужих сайтов и на чужие адреса отклоняются.
- Страницы окна отдаются со строгой политикой безопасности (CSP): только свои скрипты и стили, встраивание в чужие страницы запрещено.
- Процесс ядра может соединяться только с этим компьютером (127.0.0.0/8 и ::1).
- На одну папку данных работает только одно ядро.

```

  service.py      сборка и остановка ядра
  supervisor.py   перезапуск ядра при сбоях

  core/           задачи, расписание, слежение, уведомления, настройки

  desktop/        запуск окна в Edge или Chrome и связь с ядром
  web/            интерфейс окна: HTML, CSS и JavaScript без сборки и внешних зависимостей
  sources.py      точка подключения сборщиков
tests/            тесты
```

## Тесты

`py -3 -m unittest discover -s tests -v`: 60 тестов, около 10 секунд. Проверяются расчёты и нормализация, API, команды, запуск, подключение и остановка ядра, а также окно: поиск браузера, вход по одноразовой ссылке, остановка своего ядра после закрытия окна, раздача файлов интерфейса и целостность его модулей. Внешний вид экранов тесты не проверяют.
