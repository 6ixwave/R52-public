## Что исправлено

1. Передача выбранного прокси в HTTP WB, Ozon, AliExpress, подготовительный запрос Farpost и браузеры Ozon/AliExpress. `pw_fetch.py` преобразует адрес в формат Playwright, включая реквизиты и IPv6. Отсутствие списка сохраняет прежнее прямое соединение. Внешний прокси не создан и не настроен.
2. AliExpress: браузер возвращает `html` и `final_url`. `discovery.collect_links` принимает словарь и HTTP Response, проверяет статус, адрес и HTML. Прежний AttributeError устранён в офлайн-воспроизведении; `rendered` остаётся boolean, а не HTML.
3. ProxyPool: успех/ошибка относятся к действительно выбранному серверу, включая отдельные потоки. Сессия браузера сообщает исходный прокси. В предупреждении больше не печатается полный адрес с реквизитами. Алгоритм выбора/ротации не менялся.
4. WB: поддержаны вложенные `sizes[].price`, сохранены ID вариантов и пути evidence. Минимум вариантов не назначается всей карточке; наличие не выводится из цены. Невалидные числа отбрасываются.
5. Поиск WB/Ozon/Avito/Farpost: HTTP-ошибка, короткий ответ, ошибка запроса/формата больше не превращаются в обычную пустую выдачу. Проверены коды 403/404/429/500.
6. Farpost: `/search` заменён на `/dir` по реально прочитанной форме главной; передаётся `page`. Перенаправление `/verify` диагностируется отдельно. Это не подтверждает доступ к результатам.
7. AliExpress JSON-LD: `UNAVAILABLE` больше не распознаётся как `AVAILABLE`; значения Schema.org InStock/OutOfStock/PreOrder сопоставляются точно.
8. AliExpress HTML: слова наличия внутри script/style/template/noscript, комментариев и атрибутов больше не используются как текстовый признак наличия. Исправление воспроизведено на локальных примерах до/после. Привязка оставшегося текста страницы к конкретному SKU требует отдельной проверки.
9. Добавлен тест настоящего дочернего процесса: ошибка `SEARCH_HTTP_403` доходит через runner/worker до статуса источника и журнала с traceback. Задача PARTIAL, ложные товары не создаются. Только источник в этом тесте заменён локальным объектом, сеть не используется.

Существующие HTTP/браузерные способы сбора сохранены. Новые механизмы преодоления CAPTCHA/блокировок не реализованы. Рабочая БД, исторические наблюдения и настройки владельца этой правкой не изменялись.

## Конфигурация и оставшиеся риски

- При повторной проверке файл `%LOCALAPPDATA%\R52\collectors\proxies.json` отсутствует. В сохранённых журналах use_proxies=True, total=0, alive=0. Включённая опция не означает существование рабочего пула.
- Настройка «только этот компьютер» ограничивает входящий доступ к локальному ядру. Она не создаёт прокси и сама по себе не устраняет HTTP 403 или DNS-сбой внешнего источника.
- Старые настройки: broad_search включён; интервалы по defaults: поиск 3600 с, обновление 21600 с, лимит новых 20. В этом этапе настройки владельца не менялись.
- Пустой COMPLETED с sources={} означает отсутствие задач, подошедших по времени, а не успех всех источников.
- В Ozon остаётся verify=False, в браузере AliExpress ignore_https_errors=True. Проверки TLS не восстанавливались и не ослаблялись в этом этапе; нельзя гарантировать защиту трафика с внешним прокси.
- Вложенные HTTPAdapter/ручные повторы, неиспользуемый PROXY_COOLDOWN и сроки завершения процессов требуют отдельного ограниченного аудита.
- AliExpress: глобальные текстовые признаки наличия, связь цены с SKU и переход RU→COM требуют проверки на реальных сохранённых ответах. Исправленные частные дефекты не делают весь парсер достоверным автоматически.
- READY в реестре означает наличие класса, а не проверенный live-доступ. Содержимое существующих браузерных профилей не аудировано; гарантий отсутствия риска блокировки аккаунтов нет.
