R-52 предназначена для автономного поиска предложений, накопления истории цен, сравнения условий, слежения и общения с владельцем. Текущий продукт: локальное Windows-приложение с Python HTTP-ядром, SQLite, HTML/JS/CSS интерфейсом и отдельным браузерным окном. Запуск R52.cmd; сам факт использования браузерного движка не делает его удалённым сайтом. Визуальный стиль тёмный, Sonar/карта предложений. Переделывать UI и архитектуру в этом этапе не нужно.

В проекте есть товары, наблюдения, цены, входящие Eye, избранное/слежение, уведомления, резервные копии, очередь задач, расписание и помощник. ## Архитектура и источники истины

- r52/service.py: App open/start/stop, фоновые службы и локальный API.
- r52/config.py: R52_HOME, пути и порт; фактический порт смотри в runtime, не предполагая всегда 8423. По умолчанию домашние данные Windows: %LOCALAPPDATA%\R52.
- r52/core/tasks.py: единая очередь, idempotency, отмена, общий deadline.
- r52/core/scheduler.py: первый автопрогон примерно через 15–20 с, дальнейшие такты, прежние backup/maintenance/digest.
- r52/core/autocollect.py: задания источникам, subprocess, таймаут, публикация JSON, принятие доставки.
- r52/core/handlers.py: ручной collect и автосбор теперь используют один конвейер.
- r52/collectors/runner.py, auto_worker.py: граница дочернего процесса, журнал, связь с родителем, Windows Job для потомков.
- r52/collectors/{wb,ozon,avito,farpost,aliexpress}.py: получение и разбор данных; ALIEXPRESS_RU реализован в модуле AliExpress.
- r52/collectors/base.py, proxy_pool.py, pw_fetch.py, discovery.py: существующие транспорт/прокси/браузер/выдача.
- r52/intake/folder.py и eye.py: FolderWatcher → входящие → нормализация → upsert_product/add_observation → SQLite.
- r52/api/autocollect.py и web/js/views/autocollect.js: управление и статус.
- Формат экспорта JARVIS_BR02_COLLECTOR_AUTONOMOUS сохранять. Не писать товары в БД в обход intake. Не переписывать старые миграции и исторические evidence.

Шесть источников: WB, OZON, AVITO, FARPOST, ALIEXPRESS, ALIEXPRESS_RU. READY в реестре означает наличие класса, а не проверенный доступ. Широкий поиск вращает 16 тематик на источник, а не гарантирует сбор абсолютно всего ассортимента. Поиск и обновление выполняются только при работающем ядре и соответствующих настройках.

## Что уже исправлено и проверено

Ранние этапы: передача выбранного прокси в HTTP/браузер, связь результатов с выбранным прокси, удаление реквизитов из предупреждения; совместимость dict/Response AliExpress; HTML/final_url; явные ошибки поисков; WB sizes[].price с вариантами; Farpost /dir; точный разбор JSON-LD наличия AliExpress и исключение служебных script/style/атрибутов из HTML-признаков наличия. Это не доказательство live-работы всех источников.

Последний этап касался только связки, файлы r52/collectors/*.py не изменены (сверка SHA-256):
1. Ручная задача collect больше не создаёт сборщик в ядре с use_proxies=False и не пишет в другую папку. Используется тот же subprocess → auto-inbox → FolderWatcher → intake. Сбор по source ограничен выбранным источником.
2. Уже записанные корректные JSON сохраняются при ошибке worker/close; задача остаётся PARTIAL с исходной причиной и именем журнала. Отмена/deadline не импортирует файлы, а сохраняет ограниченный архив в logs/collect-*-exports.
3. retry_after/время завершения теперь считаются после работы, а не от начала долгого прогона.
4. Цель повторно проверяется перед запуском: удалённая, выключенная или изменённая цель из старого снимка не запускается.
5. Общий deadline сохраняет сводку и диагностирует источник, не превращая весь результат в безымянную ошибку.
6. API/UI различают передачу JSON, ожидание импорта и действительно записанные наблюдения. Последние считаются из observation, а не из обещаний сборщика.
7. Приём соблюдает intake.enabled и журналирует источник/listing/inbox/observation/error. Невалидный файл не мешает обработке следующего.

Проведены реальные локальные проверки: HTTP API → расписание → настоящий дочерний процесс → JSON → FolderWatcher → БД → второе наблюдение/история → выключение/остановка. Только внешняя площадка заменена явно синтетическим источником. Проверены нормальный выход, timeout, cancel и аварийная смерть родителя: рабочий процесс и потомок завершаются. Полные итоги и журналы смотри в INTEGRATION-RU.md. Старые 105 тестов не выдавай за последний итог.
